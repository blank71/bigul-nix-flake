\section{Theory of putback triples}
\label{sec:putback-triples}

\begin{theorem}[soundness of putback triples] \label{thm:putback-soundness}
\[ |(ASSERT R) ~ b ~ (ASSERT R')| \quad|=>|\quad |(all(s, v)) R s v => (some(s')) put b s v = Just s' && R' s' s v| \]
\end{theorem}

\begin{theorem}[partial forward consistency]
\[ |(ASSERT R) ~ b ~ (ASSERT(s' _ v || R' s' v))| \quad|=>|\quad |(all(s, v)) get b s = Just v && R s v ~ => R' s v| \]
\end{theorem}
\begin{proof}
Suppose |get b s = Just v| and |R s v|.
By GetPut, we have |put b s v = Just s|, and by \autoref{thm:putback-soundness}, we have |put b s v = Just s' && R' s' v|.
Thus |s = s'|, and we obtain |R' s v|.
\end{proof}

\section{Theory of range triples}
\label{sec:range-triples}

\begin{theorem}[soundness of range triples] \label{thm:range-soundness}
\[ |(ASSERTRANGE R) ~ b ~ (ASSERTRANGE P)| \quad|=>|\quad |(all(s)) P s => (some(v)) get b s = Just v && R s v| \]
\end{theorem}

Thanks to well-behavedness, we can rewrite the right-hand side of \autoref{thm:range-soundness} into a statement primarily about |put|:

\begin{lemma}
The right-hand side of \autoref{thm:range-soundness} is equivalent to
\[ (|(all(s')) P s' => (some(s, v)) put b s v = Just s' && R s v|) \quad|&&|\quad (|(all(s, v)) P s && get b s = Just v ~ => ~ R s v|) \]
\end{lemma}

The left conjunct is the primary way in which we think about these new triples: if |(ASSERTRANGE R) b (ASSERTRANGE P)| can be derived, then the \emph{range} of results of applying |put b| to those inputs satisfying~|R| will be at least~|P|.
Hence the name \emph{range triples}.
The right conjunct says that there is a ``side effect'' when we think about these triples in the putback direction: the subset of inputs considered will be forced to include those related by |get| with its domain restricted to~|P|.
So, for example, we will not be able to deduce |(ASSERTRANGE(m n || m = n+1)) replace (ASSERTRANGE(_))| even though the left conjunct is true for this pair of |R|~and~|P|.
This ``side effect'' normally does not get in the way, though, since the preconditions we specify are normally larger than the consistency relations, which contain the |get| functions.

\begin{theorem}[total forward consistency] \label{thm:total-forward-consistency}
\[ |(ASSERT R) ~ b ~ (ASSERT(s' _ v || R' s' v))| \quad|&&|\quad |(ASSERTRANGE R) ~ b ~ (ASSERTRANGE P)| \quad|=>|\quad |(all(s)) P s => (some(v)) get b s = Just v && R' s v| \]
\end{theorem}

We will write
\[ |(ASSERT R) ~ b ~ (ASSERT R') (ASSERTRANGE P)| \quad\text{as an abbreviation of}\quad |(ASSERT R) ~ b ~ (ASSERT R') ~ ~ && ~ ~ (ASSERTRANGE R) ~ b ~ (ASSERTRANGE P)| \]

\begin{theorem}[finite expansion of putback triples]
Let |f : (S <~ V) -> (S <~ V)| and |measure : S -> V -> Nat|.
If, for all |n : Nat| and |rec : S <~ V|,
\[ |((all m) (ASSERT(R && (COM(s v || measure s v = m && m < n)))) ~ rec ~ (ASSERT R'))| \quad|=>|\quad |(ASSERT(R && (COM(s v || measure s v = n)))) ~ f rec ~ (ASSERT R')| \]
then, for all |l : Nat| and |n : Nat| such that |n <= l|,
\[ |(ASSERT(R && (COM(s v || measure s v = n)))) ~ expand (suc l) f ~ (ASSERT R')| \]
\end{theorem}

\begin{corollary} For all |l : Nat|,
\[ |(ASSERT(R && (COM(s v || measure s v <= l)))) ~ expand (suc l) f ~ (ASSERT R')| \]
\end{corollary}

\begin{theorem}[finite expansion of range triples]
Let |f : (S <~ V) -> (S <~ V)|, |measure : S -> V -> Nat|, and |P : Nat -> (POWER S)|.
If, for all |n : Nat| and |rec : S <~ V|,
\[ |((all m) (ASSERTRANGE(R && (COM(s v || measure s v = m)))) ~ rec ~ (ASSERTRANGE(P m && (COM(_ || m < n)))))| \quad|=>|\quad |(ASSERTRANGE(R && (COM(s v || measure s v = n)))) ~ f rec ~ (ASSERTRANGE(P n))| \]
then, for all |l : Nat| and |n : Nat| such that |n <= l|,
\[ |(ASSERTRANGE(R && (COM(s v || measure s v = n)))) ~ expand (suc l) f ~ (ASSERTRANGE(P n))| \]
\end{theorem}
\begin{corollary}
For all |l : Nat|,
\[ |(ASSERTRANGE(R && (COM(s v || measure s v <= l)))) ~ expand (suc l) f ~ (ASSERTRANGE(LUB(n <= l) P n))| \]
\end{corollary}

\section{Verifying key-based alignment}
\label{sec:key-based-alignment}

Several variants of alignment have been implemented in BiGUL~\citep{Zan-Brul, Mendes-delta-alignment}.
Here we choose to verify a variant that is non-trivial and yet not overly complicated: key-based alignment.

For now, \citet{Barbosa-matching-lenses}'s matching lenses may be more sophisticated, but they are special-purpose and require the invention of a new framework in which everything is built from scratch.
Instead, we strive to implement all lenses from just a fixed set of primitives, aiming to promote bidirectional programming to the same status as general-purpose programming.

\begin{code}
keyAlign : Eq K => (S -> K) -> (V -> K) -> (S <~ V) -> (V -> S) -> ([S] <~ [V])
keyAlign ks kv b c =
  case
    normal [] [] exit []
      rearrV [] -> ()
         skip const ()
    normal (s :: _) (v :: _) | ks s == kv v exit (_ :: _)
      rearrS (s :: ss) -> (s, ss)
        rearrV (v :: vs) -> (v, vs)
             b
          *  keyAlign ks kv b c
    adaptive (_ :: _) []
      \ _ _ -> []
    adaptive ss (v :: vs) | kv v `elem` map ks ss
      \ ss (v :: _) -> extract ks kv v ss
    adaptive _ (_ :: _)
      \ ss (v :: _) -> c v :: ss
\end{code}

\begin{code}
extract : Eq K => (S -> K) -> (V -> K) -> V -> [S] -> [S]
extract ks kv v []         = []
extract ks kv v (s :: ss)  | ks s == kv v  =  s :: ss
                           | otherwise     =  case extract ks kv v ss of
                                                []         -> s :: []
                                                s' :: ss'  -> s' :: s :: ss'
\end{code}

\section{Discussion}
\label{sec:discussion}

A proper characterisation of the behaviour of composition will be essential for avoiding problems about composition as discussed by, e.g., \citet[Section~2.2]{Diskin-delta-asymmetric}.
\[ \begin{array}{l}
|(ASSERT (a b' || (some(b, c)) R a c && R' a b && U' b' b c)) ~ l ~ (ASSERT(COM(a' _ b || R' a' b) && T') (ASSERTRANGE P)| \\
|(ASSERT (b c || (some(a)) R' a b && R a c)) ~ r ~ (ASSERT U')|
\\ \hline
|(ASSERT(R && (COM(a _ || P a)))) ~ l . r ~ (ASSERT(a' a c || (some(b, b')) T' a' a b' && U' b' b c ))|
\end{array} \]
This requires the putback and range triples be defined mutually inductively.
A mutually inductive treatment can also shift the disjointness requirement to the ranges of normal branches instead of their exit conditions, allowing the exit conditions to be specified trivially, which can have a serious impact on runtime efficiency in the forward direction, but can be helpful when prototypic or experimental programs need to be developed without too much time for careful reasoning.

It has been realised~\citep[Section~4.1]{Stevens-QVT}\todo{some other citations}\ that, for practical bidirectional applications, a declarative approach --- in the sense that the programmer writes down only a consistency relation and relies on the system to derive a well-behaved but otherwise arbitrary implementation --- is hardly enough.
The BX community currently concentrates on the exploration of more forms of well-behavedness properties, but we should not be satisfied with only well-behavedness guarantees; instead, we should also start aiming to precisely characterise the behaviour of bidirectional programs, treating bidirectional programming seriously as we treat general-purpose programming.

We need general and formal reasoning principles for bidirectional programming to make it become a proper discipline of programming.

Programming languages should be shipped with reasoning principles; even domain-specific languages deserve domain-specific reasoning principles!

\textit{Why isn't the title of this paper ``An Axiomatic Basis for \emph{Putback-Based} Bidirectional Programming''?}
Within the realm of asymmetric lenses, the get-based approach is fundamentally just about \emph{programming consistency specifications}; only with the putback-based approach can we start talking about \emph{programming to meet functional specifications}, and only in this case does an axiomatic semantics make sense.

\textit{Doesn't \autoref{thm:total-forward-consistency} say that we need to reason in both directions anyway?}
Even if the sceptic reader insists that constructing the range triples requires thinking in the forward direction, they will still have to admit that, according to \autoref{thm:total-forward-consistency}, what needs to be verified in the forward direction is normally much easier than proving that |get| is contained in the consistency relation. This is because the major work has been done in the backward direction.

Completeness has not been proved, but we have shown that the logic works for various examples.

BiGUL is stateful, but only in the ``Reader'' way, in particular using the Reader monad's `|local|' operation to modify the current source and view.
Our Hoare-style logic can be said to be merely tracking how the current source and view are manipulated by implicit `|local|' operations.

It has been argued that ``putback'' is the essence of bidirectional programming~\citep{Fischer-essence-of-BX}.
We would like to amend this statement: Putback-based \emph{reasoning} is the essence of bidirectional programming.
This paper has shown, with the Hoare-style logic, what such reasoning can look like.
